Flagship project · Financial time series

JEPA Transformer

A two-stage forecasting model for US equities. Stage I, ArgusJEPA, is a self-supervised encoder that first learns what a single asset-day "looks like" from a sparse, point-in-time feature vector. It is then frozen, and its daily embeddings become the input sequence of Stage II, CassaFormer: a small causal Transformer (RoPE, QK-RMSNorm, Mixture-of-Experts) that forecasts the next day. Hot paths run on custom Triton kernels, kept only where they beat torch.compile.

01 · Inputs

Four sources, one vector per asset-day

02 · Stage I — ArgusJEPA · self-supervised

ArgusJEPA: predict the full view from a masked view

Each asset-day is an independent sample; this stage models no time. Half of the available features are hidden. From what is left, the context encoder and predictor must reproduce the latent that an EMA teacher computes from the full view. The loss is in embedding space, so the model learns how features relate to each other rather than reconstructing raw numbers.

03 · Freeze & hand-off

ArgusJEPA embeddings become CassaFormer's input

JEPA is trained only on the training period, then frozen. The two models never share gradients and have separate optimizers, schedules and checkpoints. The Transformer checkpoint just records which JEPA checkpoint produced its inputs.

04 · Stage II — CassaFormer · supervised

CassaFormer: causal Transformer over daily embeddings

A decoder-only stack in which each position t forecasts that day's next-day target. It has no tokenizer and no learned positional table: a bias-free linear layer maps the 256-d JEPA vector into the 128-d residual stream, and RoPE supplies order.

05 · Custom kernels

Triton only where it beats torch.compile

Every candidate kernel was A/B-tested on an NVIDIA L4 against the strongest off-the-shelf baseline: torch.compile, cuBLAS, or SDPA/FlashAttention. Parity was checked before timing, and warm-up included compilation. Two kernels survived. The backend is an explicit torch / triton / auto switch with identical state dicts, and each kernel is torch.compiler.disabled so a compiled model graph-breaks cleanly around it.

MoE expert MLP

The forward pass never writes the up/gate/activation tensors to memory, and the host never waits on token counts.

1 · Routetop-k slots sorted by expert on the GPU
2 · Tileeach expert padded to 64-row tiles, with no host sync
3 · Fused tileload tokens once; stream hidden dim through up, gate, SiLU⊙, down in registers
4 · Epiloguemultiply by router weight, write output
Backward & precision
Recomputebackward recomputes up/gate (FP16/BF16) instead of storing them
Deterministicexpert-weight grads use split, non-atomic reductions
FP32 pathgrouped GEMMs that keep up/gate; autotunes IEEE vs 3×TF32

Tile shapes are autotuned per GPU, keyed by model shape and a power-of-two token bucket that is a runtime argument, so a new batch size never recompiles.

JEPA fused first block

LayerNorm(GELU(masked_linear(x))) fused FlashAttention-style. The mask is control information only: hidden features can be NaN, and each feature keeps its own weight column.

1 · Loadzero masked features while each input tile loads
2 · On-chip rowprojection + bias → exact GELU → LayerNorm without leaving SRAM
3 · Store littlenormalized output, per-row stats, padded masked-input copy
Backward
Recomputeprojection rebuilt from the saved copy; pre-activation grad written once
1 GEMMweight gradient as a single cuBLAS call; bias/LN grads non-atomic

It runs only for strict FP32. Under FP16/BF16 autocast the encoder dispatches to PyTorch automatically, because that is faster there. The EMA teacher and encode() always use PyTorch.

06 · Design decisions

Why it is built this way

Two stages, never joint

The forecasting loss cannot reshape the representation, and JEPA is fit on the training period only. That keeps leakage boundaries simple to audit, and either model can be retrained on its own.

Per-day JEPA, temporal Transformer

JEPA learns cross-sectional structure within a single day. All multi-day dynamics belong to the Transformer, which is why the inputs carry no rolling-window statistics.

Mask by zeroing, not compaction

Hidden and missing features are zeroed inside the projection, so every feature keeps its own weight column and NaNs never reach the arithmetic. Missingness becomes something the model sees, not an imputation.

Latent L1 + EMA teacher

Predicting the teacher's embedding rather than raw values avoids fitting noise in heavy-tailed inputs. The EMA target (0.99) plus a predictor head prevents collapse without contrastive negatives.

RoPE, no learned positions

Relative position comes from rotations, so cached inference stays exact: cached keys keep their original angles. No position table has to be learned from limited financial data.

QK-RMSNorm before RoPE

Normalizing Q and K per head bounds attention-logit growth, which keeps training stable at a small width. Attention is full MHA (4 × 32), since GQA saves little at this scale.

MoE only in the middle

Blocks 2 and 3 route each day to one of 4 experts, letting different market regimes use different MLPs. The first and last blocks stay dense, so input embedding and output readout are shared.

Top-1 without renormalizing

Renormalizing a single selected gate would always give 1.0 and cut the router off from the forecast loss. Keeping the raw softmax probability preserves that gradient. Routing is dropless, with no capacity limit.

Student-t head option

Returns are heavy-tailed. The distributional head learns location, a softplus scale and degrees of freedom held above 2, so the predicted variance stays finite. It trains on NLL, while the point head uses MSE.

Leakage-safe supervision

Labels are shifted to the next day before batching. A boolean valid_mask selects the labelled positions, and windows never cross assets, continuity breaks or split boundaries.
